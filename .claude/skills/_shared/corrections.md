# Corrections (shared convention)

Local, skill-specific corrections. When you give a skill the SAME feedback more
than once, save it in that skill's `corrections/` folder as a short file so the
fix sticks permanently.

- One correction per file, named for the problem (e.g. `too-formal.md`).
- State the rule, not the story: "Put the metric before the recommendation."
- Distinct from the brains: corrections are about HOW A SKILL WRITES, not domain
  knowledge. Domain facts go to a brain via /retro.
- Promote a correction that applies to many skills into the domain CLAUDE.md or
  a brain instead of copying it around.

## Loading
Check whether the skill's `corrections/` folder holds entries. If it does, read
and apply them. If it is empty, that is the normal state — skip it and read
nothing. An empty folder costs a directory check, never a file read.
