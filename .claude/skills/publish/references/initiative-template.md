## Error Handling Expectations
- User-facing errors must be clear, actionable, and non-technical.
- System failures should provide retry options where relevant.
- Validation errors should identify the specific field or action that failed.
- Permission errors should explain that access is restricted.
- Empty states should explain why no data is available and what the user can do next.
- Critical failures should be logged and monitored.
